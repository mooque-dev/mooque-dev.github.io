<h3>Tokens First</h3>
<p>Orchid is built on a token foundation. Colors, spacing, typography, elevation, and motion are all defined as tokens flowing from Figma variables to code constants. This architecture enables theming, ensures design-dev parity, and provides the backbone for eventual product unification.</p>
<h3>Storybook as Source of Truth</h3>
<p>We adopted Storybook integrated with Chromatic to give the design team a workflow linked to GitHub. Components live in Storybook as the canonical reference for both design and engineering. Chromatic runs visual regression tests on every PR so inconsistencies surface before release, not after.</p>

<h3>A Contribution Model That Actually Works</h3>
<p>The easy path for a system this size is tight governance, the kind that protects quality by slowing everyone down. I built exactly that first, and contribution proposals dropped to near zero. I decided the formality itself was the problem, not the people ignoring it, and rebuilt around async reviews, a 48-hour turnaround, and lightweight templates. Proposals doubled overnight. Governance should reduce friction, not create it. That was a hard lesson.</p>
